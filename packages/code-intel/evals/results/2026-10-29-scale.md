## Observed capacity failure

The synthetic input contained 10,000 Python source files and one parseable pyproject.toml. Full AST hydration and reference indexing covered all 10,001 exact eligible paths without native-grammar degradation or capture loss. Bootstrap took 24.155 seconds and complete hydration 28.008 seconds on this configuration. A known symbol definition and adjacent import edge passed. Scoped semantic search for operation_9999 in module_9999.py then returned no candidates while reporting both lexical indexes ready, 10,000 indexed files and body coverage 1.0. All five offered requests completed. The family stopped at this first failure; no larger case or fresh-process restart was issued. The VM and disposable key files were deleted, independently checked against provider absence. Estimated compute cost: $0.0168 before tax, not an invoice.

Static source tracing provides a leading explanation: AST discovery configures a larger maximum; search warmup creates a separate default context and applies its 10,000-file composition cap. Its exact-file fallback also requires membership in that capped keyword corpus. The observed count discrepancy matches this path, but there was no causal rerun after failure. Next fix target: reconcile lexical and AST eligibility and expose effective search coverage/exclusions. Current results establish a failed operational check, not general semantic correctness or historical native causes.

## Exact-byte export repair and derived restoration

A deeper check found that the original harness reserialized JSON during export. That removed Journal.encode's final newline and changed Unicode escaping, breaking content-addressed blob references while retaining JSON values. Original archives are retained unchanged. Separately derived blobs reconstruct the known producer serialization and are accepted only when their exact original SHA256 and reference byte length match. This recovered all 82 original qualifier blobs and all 95 final native journal blobs; exported originals and derived bytes have separate paths and receipts. No paid measurement was rerun or replaced.

The maintained exporter now validates JSON while preserving all original octets and size limits. Four online regression controls cover exact whitespace/Unicode bytes, the real Journal producer/reference boundary, invalid JSON remaining incomplete, and qualification inventory coverage. Causal RED [40910853860](https://github.com/eren23/attocode/actions/runs/40910853860) admitted exactly three expected failures plus 127 positive controls. GREEN [40913190455](https://github.com/eren23/attocode/actions/runs/40913190455) passed all 130 controls and the exact installer/native/lifecycle smoke. All 94 post-fix native journal blobs match original SHA256/length directly, with zero restorations. The temporary RED wiring is retired, and the published product remains unchanged.

Original failures and unissued cases remain visible; there are no replacements or limit waivers. Shared-CPU timing is specific to this configuration, not a performance comparison. These small fixtures do not substitute for the paid scale results.

Only bounded evidence leaves a worker. Full-source eligibility and source/Git inventories are recorded separately from indexed coverage. Export manifests bind all original chunks by hash; incomplete export cannot earn admission. Source corpora, indexes and caches stay remote. Timing and resource observations include supervision overhead. Complete real-case supervision recorded 169.207/62.538/476.981 supervisor CPU seconds for CockroachDB/pandas/Deno respectively; nested phase supervisors add further observation work. Disk/evidence polling over large trees can be substantial. RSS is a conservative process-tree sum that can count shared pages more than once. This campaign therefore supplies operational observations and failure localization, not isolated native CPU measurements or performance comparisons.
