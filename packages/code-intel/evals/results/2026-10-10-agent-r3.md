# Agent study R3: tasks that Claude Code misses

**Status: We chose 10 tasks where Claude Code (Sonnet 5.5) with Read,
Grep and Glob had missed gold files, and where our search finds them. On
these tasks, a forced first code-intel search did not raise file Acc@5.
Acc@5 was 0.200 with the search and 0.333 without it (Δ -0.133, range
-0.300 to +0.033). Each run cost 1.40 times as much. By the rule that we
wrote before the study, this is no evidence of help. Thus we stop agent
localization studies.** A screen of 93 other tasks found few misses. Our
search has the gold files in its first 10 results on all 93 tasks, and
the agent alone had an Acc@5 hit on 89 of them (0.96). In 14 of 30 runs
with the search, the agent did not name a gold file that the search had
shown.

The study follows follow-up 5 of the [R2 pilot](2026-10-10-agent-pilot.md):
choose tasks from agent misses, not from misses of the `grep` arm. The
product source is main `97c703b`, with the shorter tool list of #148 and
#149.

## Rules

We wrote these rules in the study folder before the screen ran. We did not
change them after results existed.

- **Question.** On tasks where the agent alone misses and our search has
  the files, does `intel_first` give a higher file Acc@5 than `native`?
- **Primary metric.** The file Acc@5 of each task, as the mean of 3
  trials. The result is the mean paired difference (`intel_first` minus
  `native`), with a 95% range from a repository bootstrap.
- **Secondary.** R@10, the number of tasks where each setup is higher, the
  cost ratio, and whether the first search of `intel_first` had all gold
  files in its first 10 results.
- **Reading.** A range above 0 shows that the server helps on hard tasks.
  A range that includes 0, or a mean difference below 0.05, shows no
  evidence of help. Then we stop agent localization studies and test
  another task type, such as an edit or a review.

## Stage 1: screen

- **Pool.** Issue tasks of the R1 core mix where `product` (variant full)
  has an Acc@10 hit, and that no earlier agent study used. The pool takes
  at most 2 tasks from each repository, in hash order: 99 tasks from 81
  repositories.
- **Setup.** `native` only, 1 trial, with the model, client and prompt of
  R2. A miss is a completed run with Acc@5 below 1.
- **Tasks not run.** The harness excluded 3 tasks (MudBlazor, fluent-bit
  and floci), because their snapshots hold client guidance files. The
  httrack snapshot has a link to an absolute path. The safe extraction
  refused it, and `prepare` stopped before the 2 yt-dlp tasks. Since #151,
  `prepare` excludes such a task and continues.
- **Result.** 93 tasks from 76 repositories ran, in seven languages:
  Loc-Bench 38, LCA 23, SWE-bench Lite 12, PolyBench 11 and SWE-bench-Live
  9. No run failed. `native` had an Acc@5 hit on 89 tasks (0.96). Each of
  the 4 misses has two or three gold files, and the agent named only part
  of them.

## Stage 2: study

- **Tasks.** The 4 screen misses, and the 6 tasks that `native` missed in
  earlier studies where `product` has an Acc@10 hit. These are 10 tasks
  from 10 repositories: LCA 6, Loc-Bench 2, PolyBench 1 and SWE-bench-Live
  1. Five are in Python, four in Java and one in Kotlin. Nine tasks have
  two or three gold files.
- **Setups.** `native` and `intel_first` as in R2, with 3 new trials each:
  60 runs. The study did not use the screen trials again, so the selection
  does not favor a setup.

"Higher / lower" counts the tasks where `intel_first` is higher or lower
than `native`. The range comes from 10,000 repository bootstrap draws. p is
a sign-flip p-value over repositories. Cost is the geometric mean over
tasks, and its Δ is the ratio of `intel_first` to `native`.

**Reading.** The range of ΔAcc@5 includes 0, and the mean difference is
negative. By the rule, this is no evidence that the server helps.
`intel_first` was higher on 1 task (roms-tools) and lower on 4 (libgdx,
tock, tweepy and gson). As expected, `native` did better on some screen
misses in the new trials. For example, it had an Acc@5 hit on tweepy in
all 3 trials.

## How the agent used the search

The rules did not include these counts. They describe the 30
`intel_first` runs, and they are leads, not results.

- Each run called `semantic_search` once. The runs also made 38 Grep and
  16 Read calls in total. The 30 `native` runs made 93 Grep, 26 Read and
  8 Glob calls.
- The first search had all gold files in its first 10 results on 6 of 10
  tasks, in each trial (18 of 30 runs). On 3 tasks, it had no gold file in
  its first 10 results.
- In 14 of 30 runs, on 5 tasks, the agent did not name a gold file that
  its search had shown. On libgdx, the search showed the only gold file in
  all 3 trials, and the agent did not name it. `native` named it in 1 of 3
  trials.
- With the search, the agent named 2.13 files in each run, against 2.50
  for `native`. The prompt allows 10 files. Acc@5 counts a hit only when
  all gold files are in the first 5. Thus a short answer misses on a
  multi-file task.
- The offline reciprocal rank did not predict agent Acc@5. The Spearman
  correlation was -0.28 for `native` and -0.42 for `intel_first`.

The search often found the files. The agent named the files that it judged
most likely, and it did not add the other results.

## What this does not show

- The study has 10 tasks from 10 repositories. The MDE of ΔAcc@5 is 0.26,
  so a smaller effect can exist. The screen gave 4 misses, so the study
  has fewer tasks than the 13 to 21 that we expected.
- The tasks are hard in one way only: the gold set has more than one file,
  and the agent names only part of it. Acc@1 was 0.900 in both setups. The
  study does not test issues where the agent cannot find the main file.
- One model, one client version, one prompt and one task type. On a
  multi-file task, the prompt and Acc@5 reward a longer list, and both
  setups named about 2 files.
- `intel_first` forces one search. The study has no `intel` setup, where
  the agent chooses. In R2 batch 1, the agent called the server in 4 of 58
  such runs.
- Prompt caching continues from one run to the next, so a cost depends on
  the run order.

## Next

By the rule, we stop agent localization studies. The next agent study uses
another task type, such as an edit or a review. There, the search results
can serve more than one step, and the fixed cost of the tool list is a
smaller part of the total. The dropped search results (14 of 30 runs) are
a lead for the product. The rules did not plan this count, so a new study
must test it.

## Reproduce

The study folders are `studies/r3-screen` and `studies/r3` under
`~/Documents/AI/attocode-evals/matrix/`. The rules are in
`studies/r3-design.md`. Each trial needs a quota file that is at most one
hour old. The user writes it.

```bash
M=~/Documents/AI/attocode-evals/matrix
# Stage 1: the screen
PYTHONPATH=. python $M/studies/pick_screen.py  # writes studies/screen_ids.txt
python packages/code-intel/evals/study.py freeze --mode localize --project CHECKOUT_OF_C510A6F \
  --instances $M/runs/r1/instances.jsonl --ids $M/studies/screen_ids.txt --model claude-sonnet-5-5 \
  --trials 1 --setups native --study $M/studies/r3-screen
python packages/code-intel/evals/study.py prepare --study $M/studies/r3-screen
bash $M/studies/r3-screen/start.sh  # the wiring check, then all runs in the background with nohup
python $M/studies/r3-screen/harness/study.py summary --study $M/studies/r3-screen
# Stage 2: the study
python $M/studies/pick_r3.py  # writes studies/r3_ids.txt
ST=$M/studies/r3
python packages/code-intel/evals/study.py freeze --mode localize --project CHECKOUT_OF_C510A6F \
  --instances $M/runs/r1/instances.jsonl --ids $M/studies/r3_ids.txt --model claude-sonnet-5-5 \
  --trials 3 --setups native intel_first --study $ST
python packages/code-intel/evals/study.py prepare --study $ST
bash $ST/start.sh
python $ST/harness/study.py summary --study $ST
python -m eval.matrix.agents $ST --instances $M/runs/r1/instances.jsonl --matrix $M/runs/r1-core \
  --output $ST/agents-report.md
PYTHONPATH=. python $M/studies/r3_search_use.py $ST $M/runs/r1/instances.jsonl  # the search-use counts
```

`c510a6f` has the product source of `97c703b` and the harness of R3. The
screen ran with the harness before the last fix of #151. With `c510a6f`,
the screen excludes httrack and runs the 2 yt-dlp tasks.
