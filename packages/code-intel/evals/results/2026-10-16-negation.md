# Behavioral negation: change penalties, preserve retrieval

The narrower fix treats recognized behavioral clauses such as “without leaking
credentials” and “avoid mutating cookies” as neutral for source-exclusion penalties.
It preserves existing retrieval terms, construct expansion and snippet selection.
The previous broad rewrite remains rejected; this change does not enable it.

## Scope and implementation

`scope_exclusion_terms` recognizes a small explicit set of action leads after
`without` and `avoid`. Recognized clauses do not down-rank code implementing that
behavior. Explicit components such as `without swarm`, modifiers such as `without
unrelated swarm modules`, and `excluding examples` retain the previous penalties.
Mixed behavioral and scope clauses keep the genuine scope exclusion, including
when no punctuation separates them. Search and ambiguity/reranking diagnostics
use the same penalty interpretation.

`task_terms` is unchanged. Behavioral tails do not become new positive retrieval
terms in this bounded fix. Unknown actions and noun-based requirements retain
legacy interpretation; this is not a general natural-language parser. Queries
such as “without infinite recursion” and leading “exclude fields outside version
bounds” are outside the recognized action-lead fix.

Regression fixtures verify penalty removal in both keyword fallback and fused
search without changing the lexical query. They also cover explicit scopes,
matching-component diagnostics, mixed clauses, unchanged candidate generation,
acceptance failures and exact decision replay. All 32 new cases pass.

## Frozen judgments and actual MCP delivery

[Development](../designs/2026-10-16-negation-development.json) and
[validation](../designs/2026-10-16-negation-validation.json) each have eight new
questions across Express, Requests, ripgrep and Gson: four behavioral questions
and four scope controls, each with two distinct file judgments and pinned source
hashes, quotes and line anchors. Repositories and some implementation areas were
previously exposed; these authored, non-exhaustive labels are not independent user
or agent outcomes. Earlier queries were not relabeled as fresh evidence.

The real daily MCP evaluator requests 5, 24 and scoped results in auto mode with
2,000 tokens. It records actual output after hydration and budget trimming, and
uses a fixed first-named-result inspection policy. `--capture-generation` records
complete pre-penalty keyword, body and whole-file candidate identities, scores,
text hashes and arguments, without replacing the public search path.

| Measure | Development baseline → candidate | Validation baseline → candidate |
|---|---:|---:|
| Judged files in first-five delivered results | 10/16 → 12/16 | 10/16 → 11/16 |
| Judged files in delivered requested-24 page | 13/16 → 13/16 | 13/16 → 13/16 |
| Literal visible quotes, first five | 1 → 1 | 2 → 3 |
| Literal visible quotes, scoped page | 4 → 6 | 3 → 3 |
| Literal visible quotes after inspection | 1 → 1 | 0 → 0 |
| Warm query p95, milliseconds | 49.785 → 49.137 | 51.477 → 49.608 |

Both sets pass the predeclared acceptance rule, with **no individual judged-file
or visible-quote losses**. Every pre-penalty generation list and its arguments are
identical across arms; every scope-control delivered result row is identical.
Total first-five source-file judgments increase 20/32 → 23/32. Scoped enclosing
ranges in validation fall 5 → 4 while visible quotes remain 3 → 3: enclosing ranges
are not proof of displayed evidence.

Each arm has private caches. Three warmed repeats supply each median. The traced
runs reuse only their own arm's cache after initial untraced development probes;
those earlier probes are retained privately and not included in the decisions.
Arm order is sequential, not randomized. These small samples and timings do not
establish general relevance or speed improvements.

The [candidate freeze](../designs/2026-10-16-negation-freeze.json) precedes validation;
no product tuning followed validation. The unchanged 68-query/five-method ranking
gate passed without replacing its baseline or thresholds. Bounded local checks
passed 896 tests (9 environment skips), scale through 10,000 files and 20 lifecycle
cycles. Upstream validation is recorded in the implementation PR.

## Reproducibility and resource bounds

The [decision](2026-10-16-negation-decision.json) replays from
[compressed exact responses and generation traces](2026-10-16-negation-observations.json.gz).
The [compressed candidate patch](../designs/2026-10-16-negation-candidate.patch.gz)
reconstructs product changes from `6d407d6`; compressed and raw hashes are recorded
in the decision. Exact engine and question hashes bind the observations.

All 16 recorded MCP processes passed their supervisor in 25.676 seconds total,
with 105.137 MiB peak managed storage and 169.203 MiB peak sampled RSS. Limits were
512 MiB disk, 1.5 GiB RSS and 180 seconds per process. Only cached source packs were
read; no upstream code execution, model requests, corpus downloads or cloud workers.
Separate bounded local/ranking reports and restart proofs are retained privately.
