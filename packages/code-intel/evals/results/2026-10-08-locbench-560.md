# Loc-Bench V1: all 560 instances

**Status: Jev `choice` reranking raised file Acc@5 on every query form, but
attocode search with Jev is still below every published system.** With the full
issue as the query, Acc@5 went from 0.377 (lexical) to 0.671 (Jev over 48
files). The published systems in the table below report 0.743 to 0.870.
The first stage limits the result. Only 76% of instances have every gold file in
the first 48 lexical files, and Jev reaches 88% of that ceiling. The next work
is retrieval, not reranking. No product default changed.

## What we ran

- **Dataset.** [Loc-Bench V1](https://huggingface.co/datasets/czlll/Loc-Bench_V1)
  at revision `c44cf3b74e07ca642cec841b471a9939907c12a7`. It has 560 Python
  instances from 165 repositories: 242 bug reports, 150 feature requests, 139
  performance issues, and 29 security issues. We kept all 560 rows.
- **Query.** The full issue (`problem_statement`), as in the published
  systems. We also ran the first line of the issue (the title), which is the
  query form of our [42-instance check](2026-10-08-blind-graded-rerank.md). Ten
  issues have only one line, so their title query is the full issue.
- **Gold.** The unique files in `edit_functions`, as in the LocAgent
  evaluation code. 484 instances have one gold file, 44 have two, 25 have
  three, 6 have four, and 1 has five.
- **Metric.** LocAgent file Acc@k: a hit when the first k files hold
  min(|gold|, k) gold files. No instance has more than five gold files, so
  Acc@5 is also strict Acc@5 (all gold files in the first five). The two
  values were equal in every arm.
- **Lexical arm.** The product's default search on a fresh worktree at
  `base_commit`, with the importance and frecency weights at zero. It reads
  400 chunks and keeps the first 48 distinct files. Its order equals the
  product default order in all 1,110 queries.
- **Jev arms.** `typesafe/jev-1.13` `choice` through OpenRouter reorders the
  first 24 or the first 48 lexical files. Each candidate is a query-focused excerpt
  of at most 1,350 characters. The 48-file arm ran on the full issue only.

## Results

All 560 instances. The range is the 2.5th to 97.5th percentile of 10,000
bootstrap draws that resample source repositories, because one repository
holds up to 26 instances.

| Arm | Query | Acc@1 | Acc@5 | Acc@10 | MRR@5 | Acc@5 range |
|---|---|---:|---:|---:|---:|---|
| Lexical | full issue | 0.191 | 0.377 | 0.529 | 0.281 | 0.322 to 0.436 |
| Jev, 24 files | full issue | 0.586 | 0.613 | 0.645 | 0.626 | 0.554 to 0.668 |
| Jev, 48 files | full issue | 0.634 | **0.671** | 0.718 | 0.683 | 0.622 to 0.721 |
| Lexical | title | 0.277 | 0.495 | 0.600 | 0.380 | 0.435 to 0.556 |
| Jev, 24 files | title | 0.557 | 0.659 | 0.680 | 0.625 | 0.602 to 0.713 |

Paired Acc@5 against the lexical arm on the same query:

| Comparison | Wins | Losses | Acc@5 gain | Range of gain |
|---|---:|---:|---:|---|
| Jev 24, full issue | 133 | 1 | +0.236 | +0.193 to +0.281 |
| Jev 48, full issue | 167 | 2 | +0.295 | +0.246 to +0.347 |
| Jev 24, title | 94 | 2 | +0.164 | +0.125 to +0.204 |

Jev almost never moved a hit out of the first five. Lexical search did better
on the title than on the full issue (0.495 against 0.377). The long issue
text adds terms that pull in unrelated files.

## Cost and time

- Jev answered 1,670 requests: 1,110 with 24 files and 560 with 48 files.
  No request fell back to the lexical order.
- The median Jev latency was 479 ms with 24 files and 552 ms with 48 files.
  The 95th percentile was 7.1 s and 13.2 s.
- The OpenRouter usage counter rose by $0.86 for the full run. Other use
  of the same key in that window also counts.
- The run took about three hours on one Mac with two or three workers. Each
  worker kept one blobless clone and one worktree on disk.
- Two zulip instances failed to clone or check out because of network
  errors. A second try passed for both. No instance is missing.

## Limits

- **Query length.** The Jev arms sent the full issue. The product cuts the
  ranking query at 512 characters, and 465 of the 560 issues are longer than
  that. The title arm is under the limit (the longest title has 159
  characters).
- **Excerpt lines.** This run picked excerpt lines with every query term. The
  product drops the terms after an exclusion word such as "without" or
  "except". This is different for 170 full issues and 5 titles. The trial now
  uses the product rule. The numbers here use the old rule.
- **Contamination.** Loc-Bench uses public GitHub issues, and 194 non-bug rows
  are older than October 2024. Jev may have seen some of these fixes in
  training.
- **Labels.** The gold files are the files that the fix edited. Other files
  can also be relevant, so the metrics count some useful answers as misses.
  MULocBench flags 10 rows as invalid. We kept them, as the published 560
  numbers do.
- **Language.** Loc-Bench is Python only.

## Reproduce

Jev sends source excerpts from these public repositories to OpenRouter. It
needs `OPENROUTER_API_KEY`. The work directory needs about 5 GB per worker.

```bash
export LOCBENCH_DIR=~/locbench560
uv run --with datasets python eval/locbench560/run.py fetch
.venv/bin/python eval/locbench560/run.py prepare
.venv/bin/python eval/locbench560/run.py shard 0 2   # run "shard 1 2" in a second shell
.venv/bin/python eval/locbench560/score.py           # writes $LOCBENCH_DIR/scores.json
```

The driver resumes from its done markers. An instance with a failed trial gets
no marker, so the next run retries it. To retry a clone or checkout failure,
delete its marker and run `run.py only <instance_id>`.
